# 📋 ВЫЖИМКА ПРОЕКТА PL-1

**Дата обновления:** 19.09.2026

## 🎯 Проект
PL-1 — приложение для общения логистов с водителями в контексте доставки товаров.

**Стек:** FastAPI + SQLAlchemy (async) + PostgreSQL + Redis + Alembic + SQLAdmin + MAX Bot API + Docker

**Репозиторий:** github.com/Softinapro/PL-1.git (приватный)

## 📚 ТЕРМИНОЛОГИЯ
- **ДеньОтгрузки** — дата (обычно завтра). Контекст всей работы.
- **Trip** — задание водителю на ДеньОтгрузки (водитель + дата)
- **Route = Рейс** — маршрут (1 маршрут = 1 документ 1С «Рейс»)
- **Point** — торговая точка (магазин)
- **Логист** — работает ТОЛЬКО в 1С, в приложении НЕ создаётся
- **Водитель** — получает задание в MAX, подтверждает/отклоняет

## 🔄 БИЗНЕС-ЛОГИКА

### Основной поток
1. 1С создаёт заказы на доставку в торговые точки
2. Логист в 1С формирует маршруты (по географии + весу)
3. 1С отправляет в приложение через POST /import/trips (с X-API-Key)
4. Trip создаётся со статусом PENDING
5. Уведомление отправляется водителю в MAX (если привязан)
6. Водитель: Подтвердить всё / Отказаться от маршрута / точки / всего
7. 1С периодически запрашивает GET /export/trips?date=YYYY-MM-DD
8. 1С видит статусы (PENDING/CONFIRMED/REJECTED)
9. Логист в 1С пересобирает маршруты
10. 1С повторно импортирует через POST /import/trips → затирает старый Trip
11. Итерация до финала: все подтверждены

### Ключевые правила
- Дата отгрузки всегда уникальная (в системе активна одна дата)
- Точка в один день — в одном маршруте, в разные дни — в разных
- Вес приходит по каждой точке из 1С
- Новый импорт ЗАТИРАЕТ старый Trip (удаление + создание нового)
- Отказы водителя НЕ хранятся отдельно — только в статусах Point/Route/Trip
- Дашборд логиста НЕ делаем — 1С сама забирает данные через API
- История отказов НЕ нужна — всё в текущих статусах

## 📊 МОДЕЛИ БД

### User
- phone (String(20), unique, not null, index)
- full_name (String(100), not null)
- code (String(10), unique, nullable, index) — код из 1С (физлица)
- role (Enum: admin/logist/driver)
- is_active (Boolean, default True)
- is_archived (Boolean, default False)
- max_user_id (String(100), unique, nullable) — ID в MAX для отправки

### DriverProfile
- user_id (FK), max_user_id (String(100), unique, nullable), is_verified

### Trip (задание на ДеньОтгрузки)
- driver_id (FK users.id, not null, index)
- logist_id (FK users.id, nullable, index) — всегда None
- logist_code (String(10), nullable, index) — код логиста из 1С
- date (Date, not null, index)
- status (Enum: PENDING/SENT/CONFIRMED/PARTIAL/REJECTED)
- sent_at (DateTime, nullable)
- info (String(300), nullable)

### Route (маршрут = рейс)
- trip_id (FK trips.id, not null, index)
- order_number (Integer, not null)
- name (String(255), nullable)
- status (Enum: PENDING/CONFIRMED/REJECTED)
- rejection_reason (Text, nullable)
- address_start (String(255), not null)
- address_end (String(255), not null)

### Point (торговая точка)
- route_id (FK routes.id, not null, index)
- code (String(10), not null, index)
- date (Date, not null, index)
- order_number (Integer, not null)
- address (String(255), not null)
- weight (Numeric(10, 3), nullable)
- status (Enum: PENDING/CONFIRMED/REJECTED)
- rejection_reason (Text, nullable)
- UniqueConstraint (code, date) — uq_point_code_date

## 🔐 API-КЛЮЧ ДЛЯ 1С (IMPORT_API_KEY)
- Формат: 64 hex-символа
- Хранение: backend/.env (не коммитить)
- Заголовок: X-API-Key
- Проверка: verify_api_key в deps/auth.py
- Применяется: для всех эндпоинтов 1С

### Ротация
1. openssl rand -hex 32
2. Обновить в .env
3. docker compose restart backend
4. Обновить в 1С

## 📨 УВЕДОМЛЕНИЯ В MAX

### Формат уведомления (Вариант B)
🚛 Вам назначен рейс на 20.09.2026.
Маршрутов: 2
Точек: 5
Общий вес: 750.5 кг
👉 [Открыть]

### Логика
- После commit в import_trips.py → вызов send_trip_notification
- Одно уведомление на Trip
- Если max_user_id нет → запись в errors, Trip всё равно создан
- Итоги считаются из входных данных (calculate_totals)

### Ключевые функции в max_bot.py
- send_message(user_id, text) — базовое
- send_notification(user_id, trip_id, trip_date, routes_count, points_count, total_weight) — с деталями

### Ключевые функции в import_trips.py
- calculate_totals(routes) → dict(routes_count, points_count, total_weight)
- send_trip_notification(driver, trip_id, trip_date, routes_count, points_count, total_weight) → dict(sent, error)
