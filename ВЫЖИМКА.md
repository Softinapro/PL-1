# 📋 ВЫЖИМКА ПРОЕКТА PL-1

**Дата обновления:** 04.10.2026

## 🎯 Проект
PL-1 — приложение для общения логистов с водителями в контексте доставки товаров.

**Основная задача:** планирование логистики на следующий день.
**Философия:** приложение — инструмент общения, не система строгого учёта. Результаты уведомительные.

**Стек:** FastAPI + SQLAlchemy (async) + PostgreSQL + Redis + Alembic + SQLAdmin + MAX Bot API + Docker

**Репозиторий:** github.com/Softinapro/PL-1.git (приватный)

## 📚 ТЕРМИНОЛОГИЯ
- **Дата отгрузки** — всегда приходит из 1С. Актуальная дата планирования (обычно «завтра» в бизнес-смысле, но в приложении это просто дата). Приложение НЕ вычисляет дату (не today, не today+1). Прошлое — живёт в БД для анализа, сейчас не трогаем. Будущее после актуальной даты — не существует.
- **Trip** — задание водителю на дату (водитель + дата). **Один Trip на водителя в день.** Внутри — несколько Route.
- **Route = Рейс** — маршрут (1 маршрут = 1 документ 1С «Рейс»).
- **Point** — торговая точка (магазин).
- **Логист** — работает ТОЛЬКО в 1С, в приложении НЕ создаётся.
- **Водитель** — получает задание в MAX, подтверждает/отклоняет.

## 🔄 БИЗНЕС-ЛОГИКА

### Основной поток
1. 1С создаёт заказы на доставку
2. Логист в 1С формирует маршруты (по географии + весу)
3. 1С → POST /api/v1/import/trips (X-API-Key, формат {date, trips})
4. Trip создаётся со статусом PENDING
5. Уведомление водителю в MAX (если привязан) — с кнопками Подтвердить/Отказаться
6. Водитель: Подтвердить всё / Отказаться (от всего / частично — маршруты/точки)
7. 1С → GET /api/v1/export/trips?date=...
8. 1С видит статусы, пересобирает, повторно импортирует
9. Итерация до финала

### Ключевые правила
- Дата отгрузки всегда уникальная (в системе активна одна дата)
- Новый импорт ЗАТИРАЕТ старый Trip (delete + insert)
- Отзыв предложения = ФИЗИЧЕСКОЕ удаление Trip (не мягкое)
- Отказы хранятся только в статусах Point/Route/Trip
- Причина отказа — из справочника RejectionReason (редактируется в SQLAdmin)
- Если справочник непустой — водитель ОБЯЗАН выбрать причину
- Логист сам решает: завершить маршрутизацию или пересобрать

## 📊 МОДЕЛИ БД

### User
phone (String(20), unique, not null, index) · full_name (String(100)) · code (String(10), unique, nullable, index) · role (Enum: admin/logist/driver) · is_active (Boolean) · is_archived (Boolean) · max_user_id (String(100), unique, nullable) · created_at · updated_at

### DriverProfile
user_id (FK) · max_user_id · is_verified · created_at · updated_at

### Trip
driver_id (FK users.id) · logist_id (FK, nullable, всегда None) · logist_code (String(10), nullable) · date (Date, index) · status (Enum: PENDING/SENT/CONFIRMED/PARTIAL/REJECTED) · sent_at (DateTime, nullable) · info (String(300), nullable) · created_at · updated_at

### Route (маршрут = рейс)
trip_id (FK trips.id) · order_number (Integer) · name (String(255), nullable) · status (Enum: PENDING/CONFIRMED/REJECTED) · rejection_reason (Text, nullable) · created_at · updated_at
❌ address_start, address_end — УДАЛЕНЫ (миграция e074509c7497)

### Point
route_id (FK routes.id) · code (String(10)) · date (Date, index) · order_number (Integer) · address (String(255)) · weight (Numeric(10,3), nullable) · status (Enum: PENDING/CONFIRMED/REJECTED) · rejection_reason (Text, nullable) · created_at · updated_at
UniqueConstraint (code, date) — uq_point_code_date

### RejectionReason
scope (Enum: TRIP/ROUTE/POINT, index) · text (String(255)) · is_active (Boolean, default True) · created_at · updated_at
Мягкое удаление через is_active. Редактируется в SQLAdmin.

### MaxWebhookLog
Логи входящих вебхуков.

## 🔐 API-КЛЮЧ ДЛЯ 1С
IMPORT_API_KEY — 64 hex. Заголовок X-API-Key. Проверка: verify_api_key в deps/auth.py.

## ✅ ЭНДПОИНТЫ

### Для 1С (X-API-Key)
- POST /api/v1/import/drivers — импорт водителей
- POST /api/v1/import/trips — импорт рейсов {date, trips}
- POST /api/v1/import/trips/revoke — отзыв {date, driver_codes}
- GET /api/v1/export/trips?date=YYYY-MM-DD

### Для водителей (JWT)
- POST /api/v1/auth/login
- POST /api/v1/auth/max/bind

### Вебхук MAX
- POST /webhook — БЕЗ префикса /api/v1 (подключён отдельно)

### Служебные
- GET /health — без префикса
- GET /api/v1/ping
