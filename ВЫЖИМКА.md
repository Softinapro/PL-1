# 📋 ВЫЖИМКА ПРОЕКТА PL-1

## 🎯 Проект
**PL-1** — приложение для общения логистов с водителями в контексте доставки товаров.

**Стек:** FastAPI + SQLAlchemy (async) + PostgreSQL + Redis + Alembic + SQLAdmin + MAX Bot API + Docker

**Репозиторий:** github.com/Softinapro/PL-1.git (приватный)

## 📚 ТЕРМИНОЛОГИЯ (КРИТИЧНО!)
- ДеньОтгрузки — дата (обычно завтра). Контекст всей работы.
- Trip — задание водителю на ДеньОтгрузки (водитель + дата)
- Route = Рейс — маршрут (1 маршрут = 1 документ 1С «Рейс»)
- Point — торговая точка (магазин)
- Покупатель — владелец торговых точек
- Логист — формирует маршруты, отправляет задания
- Водитель — получает задание, подтверждает/отклоняет

Правило: Рейс ≡ Маршрут. Не путать с router из FastAPI.

## 🔄 БИЗНЕС-ЛОГИКА

### Основной поток
1. 1С создаёт заказы на доставку в торговые точки
2. Логист формирует маршруты (по географии + весу)
3. Вес не предусмотреть заранее → логист корректирует вручную
4. Импорт в приложение через POST /import/trips
5. Trip создаётся со статусом PENDING
6. Водитель получает уведомление в MAX
7. Водитель: Подтвердить всё / Отказаться от маршрута / точки / всего
8. Логист видит отказы в дашборде (real-time)
9. Логист пересобирает → затирает старым → новое уведомление
10. Итерация до финала: все подтверждены или водитель исключён
11. 1С забирает результаты (по таймеру, через API)

### Ключевые правила
- Дата отгрузки всегда уникальная (в системе активна одна дата)
- Точка в один день — в одном маршруте, в разные дни — в разных
- Вес приходит по каждой точке из 1С
- Новый импорт затирает старый Trip (удаление + создание нового)
- Отказы водителя сохраняются даже после удаления Trip
- Водитель может откатить отказ — логист видит сразу
- Логист не предлагает повторно отказанное (пока водитель не снял отказ)

### Сценарий с отменой
1. Водитель отказался от точки/маршрута
2. Логист видит → удаляет весь Trip → ищет другого водителя
3. Водитель передумал → снимает отказ
4. Логист видит (отказ снят) → может продублировать предложение

## 📊 МОДЕЛИ БД

### User
phone (unique), full_name, role (Enum: admin/logist/driver), is_active, is_archived, max_user_id (String, unique, nullable)

### DriverProfile
user_id (FK), max_user_id (String, unique, nullable), is_verified

### Trip (задание на ДеньОтгрузки)
driver_id (FK), logist_id (FK), date (Date), status (Enum: PENDING/SENT/CONFIRMED/PARTIAL/REJECTED), sent_at (DateTime), info (String(300), nullable) ← ДОБАВЛЕНО

### Route (маршрут = рейс)
trip_id (FK), order_number, status (Enum: PENDING/CONFIRMED/REJECTED), rejection_reason (Text), address_start, address_end, name (String(255), nullable) ← ДОБАВЛЕНО

### Point (торговая точка)
route_id (FK), order_number, address, status (Enum: PENDING/CONFIRMED/REJECTED), rejection_reason (Text), weight (Numeric(10, 3), nullable) ← ДОБАВЛЕНО

### BaseModel
id, created_at, updated_at

### MaxWebhookLog
(модель есть, но пока не используется)
