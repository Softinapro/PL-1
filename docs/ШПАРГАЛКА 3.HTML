🌐 Туннель CloudPub

Важно Использовать 127.0.0.1:8000 или localhost:8000. НЕ host.docker.internal:8000 — на хосте это имя не резолвится.

1. Запустить туннель

~/clo publish http 127.0.0.1:8000
# Скопируй новый URL (уже с https://) и вставь в поле «Tunnel URL» вверху страницы.

2. Проверить, что туннель работает

curl -k -X POST "{{TUNNEL}}/webhook" -H "Content-Type: application/json" -d '{"test": true}'
{"status":"ok"}

3. Посмотреть активные туннели

~/clo ls

4. Остановить туннель

pkill -f "clo publish"
Важно После перезапуска туннеля URL меняется. Обнови поле «Tunnel URL» вверху и перерегистрируй вебхук (см. ниже).

🔗 Регистрация вебхука в MAX

1. Удалить старую подписку (если есть)

curl -k -X DELETE "https://platform-api2.max.ru/subscriptions?url={{TUNNEL}}/webhook" \ -H "Authorization: {{TOKEN}}"

2. Зарегистрировать вебхук

curl -k -X POST "https://platform-api2.max.ru/subscriptions" \ -H "Authorization: {{TOKEN}}" \ -H "Content-Type: application/json" \ -d '{"url": "{{TUNNEL}}/webhook", "update_types": ["message_created", "message_callback"]}'
{"success":true}

3. Проверить активные подписки

curl -k -X GET "https://platform-api2.max.ru/subscriptions" \ -H "Authorization: {{TOKEN}}"

🧪 Тестирование MAX

1. Отправить простое сообщение (Python)

🗄️ Работа с БД (psql)

Сервис В docker compose exec использовать postgres, не db.

1. Подключиться к БД

docker compose exec postgres psql -U logistics_user -d logistics_db

2. Все пользователи

docker compose exec postgres psql -U logistics_user -d logistics_db -c "SELECT id, phone, full_name, code, role, max_user_id FROM users ORDER BY id;"

3. Найти водителя по max_user_id

docker compose exec postgres psql -U logistics_user -d logistics_db -c "SELECT * FROM users WHERE max_user_id = '63244418';"

4. Привязать max_user_id к водителю

docker compose exec postgres psql -U logistics_user -d logistics_db -c "UPDATE users SET max_user_id = '63244418' WHERE code = '0001234567';"

5. Все Trip'ы на дату

docker compose exec postgres psql -U logistics_user -d logistics_db -c "SELECT t.id, u.full_name, t.date, t.status FROM trips t JOIN users u ON u.id = t.driver_id WHERE t.date = '2026-10-06' ORDER BY t.id;"

6. Все Route / Point по Trip

docker compose exec postgres psql -U logistics_user -d logistics_db -c "SELECT r.id AS route_id, r.name, r.status, p.id AS point_id, p.code, p.address, p.weight, p.status FROM routes r LEFT JOIN points p ON p.route_id = r.id WHERE r.trip_id = 1 ORDER BY r.order_number, p.order_number;"

7. Все причины отказа

docker compose exec postgres psql -U logistics_user -d logistics_db -c "SELECT id, scope, text, is_active FROM rejection_reasons ORDER BY scope, id;"

8. Структура таблицы routes

docker compose exec postgres psql -U logistics_user -d logistics_db -c "\d routes"

🧹 Очистка и сброс

1. Удалить все Trip'ы (со всеми Route и Point)

docker compose exec postgres psql -U logistics_user -d logistics_db -c "DELETE FROM trips;"
# Cascade удалит Route и Point

2. Отвязать MAX у всех водителей

docker compose exec postgres psql -U logistics_user -d logistics_db -c "UPDATE users SET max_user_id = NULL WHERE role = 'DRIVER';"

3. Удалить причины отказа (все)

docker compose exec postgres psql -U logistics_user -d logistics_db -c "DELETE FROM rejection_reasons;"

4. Сбросить всю БД (down → volumes)

docker compose down -v && docker compose up -d
Опасно -v удалит volume с БД. После запуска — alembic upgrade head и заново создай пользователей.

📦 Alembic — миграции

1. Текущая версия

docker compose exec backend alembic current

2. Создать миграцию (автогенерация)

docker compose exec backend alembic revision --autogenerate -m "описание"

3. Применить миграции

docker compose exec backend alembic upgrade head

4. Откатить последнюю

docker compose exec backend alembic downgrade -1

5. История миграций

docker compose exec backend alembic history

🆘 Частые ошибки и решения

Ошибка Решение
Connection reset by peer Смотреть логи: docker compose logs backend --tail 50
No module named 'app' Пересобрать: docker compose up -d --build
503 Service Unavailable (туннель) Перезапустить туннель с 127.0.0.1:8000
Unknown recipient (MAX) user_id передавать в query, не в теле
SSL: CERTIFICATE_VERIFY_FAILED Добавить verify=False в httpx или сертификат Минцифры
service "db" is not running Сервис называется postgres, не db
No config file 'alembic.ini' Перезапустить бэкенд, проверить volume
invalid input value for enum userrole Использовать ADMIN, LOGIST, DRIVER (верхний регистр)
duplicate key value violates unique constraint Поле уже занято — обновляй существующую запись, не создавай дубль
