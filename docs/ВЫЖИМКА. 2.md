# 📋 ВЫЖИМКА ПРОЕКТА PL-1

**Дата обновления:** 12.10.2026

## 🎯 Проект
PL-1 — приложение для общения логистов с водителями. Планирование логистики на следующий день. Приложение — инструмент общения, результаты уведомительные.

**Стек:** FastAPI + SQLAlchemy (async) + PostgreSQL + Redis + Alembic + SQLAdmin + MAX Bot API + Docker

**Репозиторий:** github.com/Softinapro/PL-1.git (приватный)

## 📚 ТЕРМИНОЛОГИЯ
- **Активный день** = date.today() + 1 (завтра). Только для него доступны действия (подтвердить/отклонить). Прошлое — только просмотр. Будущего не должно быть.
- **Trip** — задание водителю на дату. Один на водителя в день. Внутри — несколько Route.
- **Route = Рейс** — маршрут (1 = 1 документ 1С «Рейс»). Несколько в Trip.
- **Point** — торговая точка.
- **Логист** — работает в 1С. **Водитель** — в MAX.

## 🔄 БИЗНЕС-ЛОГИКА

### Три сценария 1С (перед отправкой предложения)
1. **Trip нет** → POST /import/trips создаёт новый → «🚛 Вам назначен рейс».
2. **Trip PENDING** → затирает старый → «🔄 Предложение обновлено».
3. **Trip CONFIRMED/PARTIAL/REJECTED** → 1С анализирует отказы: либо обновить с учётом отказов, либо отозвать (POST /import/trips/revoke).

### Правила
- Новый импорт ЗАТИРАЕТ старый Trip.
- is_update определяется PL-1 автоматически (был ли Trip на (driver_id, date)).
- Отзыв = физическое удаление Trip.
- **Отказ от всего** → все Route/Point REJECTED + reason, Trip REJECTED.
- **Отказ от маршрута** → Route REJECTED + reason, все его Point REJECTED + reason.
- **Отказ от точки** → Point REJECTED + reason, Route пересчитывается (PARTIAL, если смесь).
- **Пересчёт Route по точкам:** все CONFIRMED → CONFIRMED; все REJECTED → REJECTED; есть PENDING → PENDING; смесь → PARTIAL.
- **Пересчёт Trip по Route:** аналогично.
- Причины — из справочника. Если пуст — отказ без причины.
- История отказов не хранится. 1С анализирует текущие статусы.

## 📨 MAX Bot API

- **Домен:** https://platform-api2.max.ru
- **Авторизация:** Authorization: <token> (не в URL)
- **Сертификат:** verify=False (временно)

### Подписка (только API, не UI)
POST /subscriptions {"url": "<URL>/webhook", "update_types": ["message_created", "message_callback"]}
GET /subscriptions
DELETE /subscriptions?url=<URL>/webhook   (URL в query!)

Каждый перезапуск cloudpub → новый URL → обновить подписку.

### Отправка
POST /messages?user_id=<sender.user_id> — user_id в query!

Тело:
{"text": "...", "format": "html", "attachments": [{"type": "inline_keyboard", "payload": {"buttons": [[{"type": "callback", "text": "...", "payload": "..."}]]}}]}

chat_id из вебхука НЕ подходит для отправки. Использовать sender.user_id.

### Ответ на callback
POST /answers?callback_id=<id>

### Редактирование
PUT /messages?message_id=<mid>

### Формат message_created
{"message": {"recipient": {"chat_id": 443354194}, "body": {"mid": "mid...", "text": "..."}, "sender": {"user_id": 63244418, "first_name": "..."}}, "update_type": "message_created"}

### Формат message_callback
callback = data.get("callback", {})
payload = callback.get("payload", "")
max_user_id = callback.get("user", {}).get("user_id")
callback_id = callback.get("callback_id")
message в callback ОТСУТСТВУЕТ!

## 🌐 Туннель cloudpub

- Команда: ~/clo publish http 127.0.0.1:8000
- НЕ host.docker.internal:8000
- nohup НЕ РАБОТАЕТ — процесс умирает. Использовать tmux:
  tmux new -s clo
  ~/clo publish http 127.0.0.1:8000
  Ctrl+B, D
- URL меняется при перезапуске.
- При недоступности: проверить ps aux | grep clo publish, ~/clo ls, tail ~/clo.log.
