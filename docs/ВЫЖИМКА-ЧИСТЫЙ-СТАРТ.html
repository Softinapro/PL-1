🧹 Чистый старт миграций Alembic

Проект: Логистика для водителей (FastAPI + MAX + Docker)

Путь: ~/projects/PL-1

Когда применять: перед переходом в прод, когда все dev-миграции накопились и не имеют смысла.

⚠️ ВНИМАНИЕ

Все dev-данные пропадут: тестовые User'ы, Trip'ы, Route, Point, причины отказа.

Делай это осознанно и перед релизом. Перед началом — сделай бэкап БД, если данные нужны.

⚠️ Перед началом — проверь

1. Модель и БД синхронны

docker compose exec backend alembic revision --autogenerate -m "check"

Открой сгенерированный файл. Если внутри только комментарии (нет op.create_table, op.add_column, op.drop_column) — всё ок, можно чистить.

Если есть изменения — сначала разберись с ними. Удали тестовую миграцию:

rm backend/alembic/versions/<хэш>_check.py

2. Бэкап БД (если нужны данные)

docker compose exec postgres pg_dump -U logistics_user logistics_db > backup_$(date +%Y-%m-%d).sql

🔧 Пошагово

Шаг 1. Остановить всё

cd ~/projects/PL-1 && docker compose down

Шаг 2. Удалить все файлы миграций

rm backend/alembic/versions/*.py
Проверка:
ls backend/alembic/versions/
Папка должна быть пустой (или только __pycache__, .gitkeep)

Шаг 3. Удалить volume БД

docker compose down -v
Опасно Флаг -v удалит volume с БД. Вся БД пропадёт.
Проверка:
docker volume ls | grep pl-1
Пусто — volume удалён

Шаг 4. Запустить контейнеры заново

docker compose up -d
Подожди 15-20 секунд, потом проверь:
docker compose ps
Все три: Up (healthy) или Up

Шаг 5. Сгенерировать initial schema

docker compose exec backend alembic revision --autogenerate -m "initial schema"
Проверка — должен быть один файл:
ls backend/alembic/versions/

Открой его и убедись, что там:

  • op.create_table('users', ...)
  • op.create_table('trips', ...)
  • op.create_table('routes', ...)
  • op.create_table('points', ...)
  • op.create_table('driver_profiles', ...)
  • op.create_table('rejection_reasons', ...)
  • op.create_table('max_webhook_logs', ...)
  • Все индексы, констрейнты, enum'ы

Шаг 6. Применить миграцию

docker compose exec backend alembic upgrade head
Running upgrade -> <хэш>, initial schema
Проверка:
docker compose exec backend alembic current
<хэш> (head)

Шаг 7. Проверить, что БД создалась

docker compose exec postgres psql -U logistics_user -d logistics_db -c "\dt"
users, trips, routes, points, driver_profiles, rejection_reasons, max_webhook_logs, alembic_version

Шаг 8. Проверить, что бэкенд работает

curl http://localhost:8000/health
{"status":"ok","service":"logistics-api"}
curl http://localhost:8000/api/v1/ping
{"message":"pong"}

Шаг 9. Создать базовых пользователей

docker compose exec postgres psql -U logistics_user -d logistics_db -c " INSERT INTO users (phone, full_name, role, is_active, is_archived, created_at, updated_at) VALUES ('9001111111', 'Админ Иванов', 'ADMIN', true, false, now(), now()), ('9002222222', 'Логист Петров', 'LOGIST', true, false, now(), now()), ('9323359845', 'Водитель Сидоров', 'DRIVER', true, false, now(), now()); "
Привяжи свой MAX ID (замени 63244418 на свой):
docker compose exec postgres psql -U logistics_user -d logistics_db -c " UPDATE users SET max_user_id = '63244418', code = '0001234567' WHERE phone = '9323359845'; "

Шаг 10. Создать причины отказа

docker compose exec postgres psql -U logistics_user -d logistics_db -c " INSERT INTO rejection_reasons (scope, text, is_active, created_at, updated_at) VALUES ('TRIP', 'Поломка машины', true, now(), now()), ('TRIP', 'Заболел', true, now(), now()), ('TRIP', 'Не успеваю', true, now(), now()), ('ROUTE', 'Не успеваю', true, now(), now()), ('ROUTE', 'Дорога закрыта', true, now(), now()), ('POINT', 'Точка закрыта', true, now(), now()), ('POINT', 'Нет товара', true, now(), now()), ('POINT', 'Отказ точки', true, now(), now()); "

Шаг 11. Проверить всё в деле

  1. Напиши боту в MAX → должен прийти ответ (меню или «не зарегистрированы»).
  2. Проверь /docs — все эндпоинты на месте.
  3. Импортируй тестовый Trip через POST /api/v1/import/trips с X-API-Key.
  4. Проверь GET /api/v1/export/trips?date=....

📌 Всё одной строкой (копипаст)

cd ~/projects/PL-1 && \ docker compose down && \ rm backend/alembic/versions/*.py && \ docker compose down -v && \ docker compose up -d && \ sleep 20 && \ docker compose exec backend alembic revision --autogenerate -m "initial schema" && \ docker compose exec backend alembic upgrade head && \ docker compose exec backend alembic current && \ docker compose exec postgres psql -U logistics_user -d logistics_db -c "\dt"
Опасно Перед запуском — проверь «Перед началом» (модель синхронна, данные не нужны).

⚠️ Важно — Git

После чистки — закоммить удаление старых миграций:

git add backend/alembic/versions/ && \ git commit -m "chore: clean alembic migrations — initial schema" && \ git push

Все старые файлы миграций удалятся из репозитория. В проде будет одна миграция initial schema.

🔄 Откат (если что-то пошло не так)

Восстановить из бэкапа

docker compose down -v && \ docker compose up -d && \ sleep 20 && \ docker compose exec -T postgres psql -U logistics_user -d logistics_db < backup_2026-10-05.sql

Или восстановить файлы миграций из Git

git checkout HEAD~1 -- backend/alembic/versions/
