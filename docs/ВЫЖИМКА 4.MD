# 📋 ВЫЖИМКА ПРОЕКТА PL-1

**Дата обновления:** 20.10.2026

## 🎯 Проект
PL-1 — приложение для общения логистов с водителями. Планирование логистики на следующий день. Приложение — инструмент общения, результаты уведомительные.

**Стек:** FastAPI + SQLAlchemy (async) + PostgreSQL + Redis + Alembic + SQLAdmin + MAX Bot API + Docker

**Репозиторий:** github.com/Softinapro/PL-1.git (приватный)

## 📚 ТЕРМИНОЛОГИЯ
- **Активный день** = date.today() + 1 (завтра). Только для него доступны действия.
- **Trip** — задание водителю на дату. Один на водителя в день. Внутри — несколько Route.
- **Route = Рейс** — маршрут (1 = 1 документ 1С «Рейс»). Несколько в Trip.
- **Point** — торговая точка.
- **Логист** — работает в 1С. **Водитель** — в MAX.

## 🔄 БИЗНЕС-ЛОГИКА

### Три сценария 1С
1. **Trip нет** → POST /import/trips создаёт → «🚛 Вам назначен рейс».
2. **Trip PENDING** → затирает старый → «🔄 Предложение обновлено».
3. **Trip CONFIRMED/PARTIAL/REJECTED** → 1С анализирует отказы: либо обновить, либо отозвать (POST /import/trips/revoke).

### Правила
- Новый импорт ЗАТИРАЕТ старый Trip.
- is_update определяется PL-1 автоматически.
- Отзыв = физическое удаление Trip.
- **Отказ от всего** → все Route/Point REJECTED + reason, Trip REJECTED.
- **Отказ от маршрута** → Route REJECTED + reason, все его Point REJECTED + reason.
- **Отказ от точки** → Point REJECTED + reason, Route пересчитывается (PARTIAL при смеси).
- **Пересчёт Route по точкам:** все CONFIRMED → CONFIRMED; все REJECTED → REJECTED; есть PENDING → PENDING; смесь → PARTIAL.
- **Пересчёт Trip по Route:** аналогично.
- Причины — из справочника. Пуст → отказ без причины.
- История отказов не хранится. 1С анализирует текущие статусы.

### Цикл с 1С
1. Водитель действует в Mini App (или боте) → данные пишутся в БД.
2. 1С опрашивает `GET /export/trips/summary?date=...` каждые 2–10 секунд.
3. Если `all_confirmed: true` → 1С фиксирует, что все согласны.
4. Если `counts.partial > 0` или `counts.rejected > 0` → 1С дёргает `GET /export/trips?date=...` для деталей.
5. Логист обрабатывает: обновляет предложение (`POST /import/trips`) или отзывает (`POST /import/trips/revoke`).

### Регистрация водителя (утверждено)
1. **1С** — источник данных. Логист заводит водителя: ФИО, **номер телефона**, код 1С.
2. **1С** выгружает водителя в Mini App (`POST /import/drivers`). В БД появляется `User` с `phone`, `code`, `full_name`, **без `max_user_id`**.
3. **Водитель** заходит в Mini App. Приложение пытается найти его по `max_user_id`.
4. **Если не найден** → экран регистрации (два варианта):
   - **Быстрая регистрация:** нажимает «Поделиться номером» → MAX отдаёт номер → бэкенд ищет `User` по телефону → привязывает `max_user_id` → JWT.
   - **Резервный вариант:** копирует **ID в MAX** и **Имя** → передаёт логисту (звонок, мессенджер). Логист вносит ID в 1С → 1С выгружает в Mini App → при следующем заходе водитель находится по `max_user_id`.
5. **При смене телефона** в 1С: `import_drivers.py` сбрасывает `max_user_id` в `NULL`. Водитель перерегистрируется (новый аккаунт MAX = новый `max_user_id`).

**Принципы:**
- Телефон — первичный ключ для связи 1С и MAX.
- `max_user_id` — кэш авторизации (сбрасывается при смене телефона).
- Имена в 1С и MAX не синхронизируются (живут своей жизнью).
- Без телефона в БД регистрация невозможна (защита от посторонних).

## 📨 MAX Bot API

- **Домен:** https://platform-api2.max.ru
- **Авторизация:** Authorization: <token>
- **Сертификат:** verify=False

### Подписка
POST /subscriptions {"url": "<URL>/webhook", "update_types": ["message_created", "message_callback"]}
DELETE /subscriptions?url=<URL>/webhook
Каждый перезапуск cloudpub → обновить подписку.

### Отправка
POST /messages?user_id=<sender.user_id>
Тело: {"text": "...", "format": "html", "attachments": [{"type": "inline_keyboard", "payload": {"buttons": [...]}}]}

### Кнопки
- `callback` — для действий внутри бота.
- `link` — для deep link (Mini App).

### Deep link
`https://max.ru/<MAX_BOT_NAME>?startapp=trip_<id>` (или `main`).

### Формат message_callback
callback = data.get("callback", {})
payload = callback.get("payload", "")
max_user_id = callback.get("user", {}).get("user_id")
callback_id = callback.get("callback_id")

### Лимиты кнопок: 210 кнопок, 30 рядов, 7 в ряду.
