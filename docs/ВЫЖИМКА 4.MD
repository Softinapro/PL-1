# 📋 ВЫЖИМКА ПРОЕКТА PL-1

**Дата обновления:** 19.10.2026

## 🎯 Проект
PL-1 — приложение для общения логистов с водителями. Планирование логистики на следующий день. Приложение — инструмент
общения, результаты уведомительные.

**Стек:** FastAPI + SQLAlchemy (async) + PostgreSQL + Redis + Alembic + SQLAdmin + MAX Bot API + Docker

**Репозиторий:** github.com/Softinapro/PL-1.git (приватный)

## 📚 ТЕРМИНОЛОГИЯ
- **Активный день** = date.today() + 1 (завтра). Только для него доступны действия. Прошлое — просмотр. Будущего не
должно быть.
- **Trip** — задание водителю на дату. Один на водителя в день. Внутри — несколько Route.
- **Route = Рейс** — маршрут (1 = 1 документ 1С «Рейс»). Несколько в Trip.
- **Point** — торговая точка.
- **Логист** — работает в 1С. **Водитель** — в MAX.

## 🔄 БИЗНЕС-ЛОГИКА

### Три сценария 1С (перед отправкой предложения)
1. **Trip нет** → POST /import/trips создаёт → «🚛 Вам назначен рейс».
2. **Trip PENDING** → затирает старый → «🔄 Предложение обновлено».
3. **Trip CONFIRMED/PARTIAL/REJECTED** → 1С анализирует отказы: либо обновить, либо отозвать (POST
/import/trips/revoke).

### Правила
- Новый импорт ЗАТИРАЕТ старый Trip.
- is_update определяется PL-1 автоматически (был ли Trip на (driver_id, date)).
- Отзыв = физическое удаление Trip.
- **Отказ от всего** → все Route/Point REJECTED + reason, Trip REJECTED.
- **Отказ от маршрута** → Route REJECTED + reason, все его Point REJECTED + reason.
- **Отказ от точки** → Point REJECTED + reason, Route пересчитывается (PARTIAL при смеси).
- **Пересчёт Route по точкам:** все CONFIRMED → CONFIRMED; все REJECTED → REJECTED; есть PENDING → PENDING; смесь →
PARTIAL.
- **Пересчёт Trip по Route:** аналогично.
- Причины — из справочника. Пуст → отказ без причины.
- История отказов не хранится. 1С анализирует текущие статусы.

### Цикл с 1С (обновлено)
1. Водитель действует в Mini App → данные пишутся в БД.
2. 1С опрашивает `GET /export/trips/summary?date=...` каждые 2–10 секунд.
3. Если `all_confirmed: true` → 1С фиксирует, что все согласны.
4. Если `counts.partial > 0` или `counts.rejected > 0` → 1С дёргает `GET /export/trips?date=...` для деталей.
5. Логист обрабатывает: обновляет предложение (`POST /import/trips` — затирает старый) или отзывает (`POST
/import/trips/revoke`).

### User
phone (String(20), unique, not null, index) · full_name (String(100)) · code (String(10), unique, nullable, index) ·

## ✅ ЭНДПОИНТЫ

### Бот и 1С (без JWT, по API-ключу)
- POST /api/v1/import/drivers
- POST /api/v1/import/trips — {date, trips}
- POST /api/v1/import/trips/revoke — {date, driver_codes}
- GET /api/v1/export/trips?date=... — полные данные (все статусы)
- GET /api/v1/export/trips/summary?date=... — **лёгкая сводка** (all_confirmed, counts, reactions)
- POST /webhook (без префикса)
- GET /health, GET /api/v1/ping

### Mini App (JWT, только DRIVER)
- POST /api/v1/auth/max/bind — обмен initData → JWT
- GET /api/v1/me/trips?date=... — рейс водителя (по умолчанию — завтра)
- GET /api/v1/me/rejection-reasons?scope=... — справочник причин
- POST /api/v1/me/trips/{id}/confirm — подтвердить всё
- POST /api/v1/me/trips/{id}/reject — отказаться (полностью/частично)

                        ## 🔧 КОД

                        ### app/core/security.py
                        Переход на **PyJWT 2.15.1**. `create_access_token`, `decode_access_token`,
                        `datetime.now(timezone.utc)`.

                        ### app/core/integrations/max_validator.py
                        `validate_init_data(raw_init_data, bot_token, max_age_seconds=3600)`. Алгоритм MAX: `secret_key
                        = HMAC(key="WebAppData", msg=bot_token)`, затем `signature = HMAC(key=secret_key,
                        msg=launch_params)`. Ручной `split("=", 1)` + `unquote` + сортировка. Проверка дубликатов
                        ключей, `compare_digest`, TTL.

                        ### app/api/v1/schemas/
                        - `auth.py` — `UserPublic`, `TokenResponse`
                        - `trips.py` — `TripPublic`, `RoutePublic`, `PointPublic`
                        - `rejection_reasons.py` — `RejectionReasonPublic`
                        - `reject.py` — `RejectRequest`, `RouteRejectItem`, `PointRejectItem`

                        ### app/api/v1/endpoints/me.py
                        - `get_active_date()` = today + 1
                        - `_build_trip_public(trip)` — собирает TripPublic с вычисляемыми полями (`routes_count`,
                        `points_count`, `total_weight`, `is_actionable`)
                        - `_recalc_route_status`, `_recalc_trip_status` — пересчёты
                        - `GET /me/trips` — только DRIVER, по умолчанию завтра
                        - `GET /me/rejection-reasons?scope=` — только DRIVER, scope обязателен
                        - `POST /me/trips/{id}/confirm` — idempotent на CONFIRMED, сбрасывает отказы, **разрешён из
                        PARTIAL/REJECTED** (водитель передумал)
                        - `POST /me/trips/{id}/reject` — формат: `{trip_reason_id, routes[], points[]}`. Нельзя
                        комбинировать trip+partial → 400. Пустой запрос → 400. Уже REJECTED → 409. CONFIRMED → разрешён
                        (водитель передумал).

                        ### app/api/v1/endpoints/auth.py
                        `POST /auth/max/bind` — принимает `X-Max-InitData`, валидирует, ищет User по `max_user_id`,
                        проверяет `is_active`/`is_archived`/`role == DRIVER`, выдаёт JWT.

                        ### app/api/v1/endpoints/export_trips.py
                        - `GET /export/trips?date=...` — все рейсы с полными данными.
                        - `GET /export/trips/summary?date=...` — **лёгкая сводка**:
