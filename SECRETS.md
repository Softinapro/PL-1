# 🔐 Секреты проекта PL-1

Документ описывает, какие секреты есть в проекте, где хранятся и как их обновлять.

## IMPORT_API_KEY

- **Назначение:** API-ключ для интеграции с 1С (импорт водителей, рейсов).
- **Кто использует:** 1С (система).
- **Хранение на сервере:** backend/.env
- **Хранение в 1С:** защищённое место (настраивается 1С-разработчиком).
- **Формат:** 64 символа hex.
- **Генерация:** openssl rand -hex 32

## Как обновить ключ (ротация)

Когда нужно:
- При компромиссе (утечка ключа)
- Плановая ротация (раз в год)
- Смена окружения (dev -> prod)

Процедура:
1. Сгенерировать новый ключ: openssl rand -hex 32
2. Зайти на сервер по SSH.
3. Открыть .env: nano backend/.env
4. Заменить значение IMPORT_API_KEY на новый ключ.
5. Перезапустить backend: docker compose restart backend
6. Обновить ключ в 1С.
7. Проверить, что запросы 1С проходят успешно.

Downtime: около 5 секунд при restart backend.

## Откат

Если новый ключ не работает:
1. Вернуть старое значение в .env.
2. Перезапустить backend.
3. Проверить.

Важно: откат только в .env. В 1С не откатывать, а разобраться.

## Безопасность

- Не коммитить .env в git (проверено .gitignore).
- Не логировать ключ целиком (только первые 4 символа при отладке).
- Не скидывать в чат, мессенджер, тикеты.
- Разные ключи для dev и prod.
- HTTPS на проде.

## Если ключ утёк

1. Немедленно сгенерировать новый.
2. Обновить в .env + restart.
3. Обновить в 1С.
4. Проверить, что старый ключ не работает.
5. Разобраться, как утёк.

## Связанные файлы

- backend/.env — реальный ключ (не коммитится)
- backend/.env.example — заглушка (коммитится)
- backend/app/config.py — поле IMPORT_API_KEY
